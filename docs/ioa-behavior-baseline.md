# IOA 行为偏离基线（设计说明）

> 目标：**没有明显攻击特征时也要给出判断**——尤其是「从来没出现过的 IP / 地址 / 域名」。
> 本文件说明口径、白名单、检测项与输出契约；实现见 `backend/app/services/behavior_baseline.py`。

---

## 1. 为什么要做

现有 74 条内置规则（另有 510 条 Sigma 导入规则）绝大多数是 **IOC/特征型**：命中已知恶意关键字、已知敏感路径、超过阈值次数。
这类规则的固有盲区是——**攻击者只要不用已知特征，就检测不到**，日志只能落到「未发现异常」。

IOA（Indicator of Attack）看的是**行为偏离**：不看"这个 IP 是不是恶意的"，而看
"这个地址在本批次里从来没出现过 / 只在罕见端口外联 / 某个账号第一次从这个来源登录"。

落点：无明确攻击特征时，结论从「未发现异常」升级为
**「未发现明确攻击特征，但存在 N 项行为偏离（低置信度）」**，并把偏离逐项列出。

---

## 2. 基线口径（本批次，不跨历史）

「从来没有出现过」需要一个比较基准。本项目分三层，**当前只做层 1 + 层 2**：

| 层 | 基线来源 | 本期 | 说明 |
|---|---|---|---|
| 层 1 | **同一次分析的记录** | ✅ 做 | 某地址在本批次只出现 1 次 → 低频/独狼行为 |
| 层 2 | **内置知识表**（私有网段、常用端口、常用域名） | ✅ 做 | 是层 1 不误报的前置条件 |
| 层 3 | **跨批次历史**（新表 `entity_baseline`） | ❌ 不做 | 需持久化实体库 + 保留策略，且会改变既有 62 个用例预期 |

**证据纪律**：所有结论必须写清口径。本期一律标注为
「**与本批次相比首次出现**」，**不得**表述为"历史首次"——那是层 3 才能给的结论。

---

## 3. 层 2：白名单（不误报的前提）

| 类别 | 内容 | 作用 |
|---|---|---|
| 私有/保留网段 | `10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`100.64/10`、`::1`、`fc00::/7`、`fe80::/10` | 内网互访天然"首次出现"，但不是信号 |
| 常用端口 | 80/443/53/123/22/3389/445/3306/5432/6379 等 | 避免把正常业务端口当"异常外联" |
| 常用域名 | Windows 更新 / 主流 CDN / 浏览器厂商 / CA-OCSP / 中国主流站点 | 避免把系统日常外联当"新域名" |
| 非公网主机名 | 单标签主机名、`.local`、`.lan`、`.internal`、`.arpa` | 内网解析不是外联信号 |

白名单是**代码内置常量**（`behavior_baseline.py`），刻意不做成配置项：
它是"不误报"的底线而不是可选项，改动应当走代码评审。

---

## 4. 检测项（层 1）

| kind | 名称 | 判据 | 关键防噪 |
|---|---|---|---|
| `rare_destination_ip` | 本批次首次出现的目的地址 | 公网目的 IP 在本批次仅出现 1 次 | 白名单网段排除 |
| `rare_domain_query` | 本批次首次出现的域名解析 | DNS 查询域名在本批次唯一且不在常用域名表 | 单标签/`.local` 排除 |
| `unusual_outbound_port` | 非常用端口外联 | 公网目的端口不在常用端口表 | 按 (目的IP, 端口) 分组计数 |
| `rare_source_ip` | 低频来源地址 | 来源 IP 在本批次仅出现 1 次 | 需配合 2xx/成功结果才算偏离 |
| `rare_url_path` | 罕见 URL 路径 | 路径在本批次唯一且返回 2xx | **仅在有基线时生效**（路径去重数 < 记录数一半），排除静态资源后缀 |

**防噪是硬要求**：`rare_url_path` 在"每个 URL 都唯一"的高基数 Web 日志上会被整体抑制——
那种情况下"唯一"不携带任何信息。同理所有项都有输出条数上限（`MAX_DEVIATIONS = 20`）。

---

## 5. 输出契约

新增 `AnalysisResult.behavior_deviations: list[BehaviorDeviation]`：

```json
{
  "kind": "rare_domain_query",
  "name": "本批次首次出现的域名解析",
  "basis": "与本批次全部记录相比仅出现 1 次",
  "detail": "WK001 查询 news.axonbyte.org，本批次内仅出现 1 次，且不在常用域名表内。",
  "count": 1,
  "evidence": ["<原始日志行>"]
}
```

**与 `events` 严格分离**，理由：

1. 行为偏离**不是攻击结论**，若混进 `events` 会污染风险定级与杀伤链；
2. `evaluation/corpus/scenario.yaml` 用整份日志断言完整事件清单，多出的事件会被判为 FP；
3. 风险等级**不因行为偏离而变化**（与 `RISK_SCORING_ENABLED` 的既有做法一致）：本期只做计算与展示。

结论文案（`analyzer._build_judgement`）三态扩展为四态：

| 条件 | 结论 | confidence |
|---|---|---|
| 有事件 | 按最高等级输出 | 0.52–0.95 |
| 无事件 + 覆盖不完整 | 无法确认 | 0.2 |
| 无事件 + **存在行为偏离** | **未发现明确攻击特征，但存在 N 项行为偏离（低置信度）** | 0.35 |
| 无事件 + 无偏离 | 未发现异常 | 0.35 |

---

## 6. 非目标（本期不做）

- ❌ 跨批次历史基线（层 3）：需要持久化实体库，且要显式更新既有语料预期。
- ❌ 罕见 User-Agent、高熵域名、高比例编码路径（规则层已部分覆盖，且误报成本高）。
- ❌ 用行为偏离升级风险等级或改变结论定级。
- ❌ 任何自动处置动作（AGENTS.md §3 产品边界）。

---

## 7. 时间维度异常

已接入 3 类低置信度时间偏离：

- 非工作时段活动：日志时间戳落在 23:00-06:00，提示核实是否为正常运维或跨时区业务；
- 同源高频突发：同一来源在短窗口内显著高于其它来源，提示核实压测、批量任务或异常高频行为；
- 周期性心跳：同一来源连续间隔高度规整，提示核实固定采集任务或心跳式外联。

这些信号仍只进入 `behavior_deviations`，不进入 `events`，不改变风险等级。

---

## 8. 验证方式

- 单元测试 `backend/tests/test_behavior_deviations.py`：
  - 正向：公网目的 IP / 域名 / 非常用端口 / 低频来源 / 罕见路径各自能命中；
  - 防噪（关键）：内网 IP、白名单域名、常用端口、静态资源、高基数 URL 日志**均不得**产生偏离；
  - 时间偏离：非工作时段、同源高频突发、周期性心跳能命中，并验证单来源批量日志不误报突发；
  - 四态结论：偏离存在时结论为「存在行为偏离」而非「未发现异常」。
- 回归：`pytest -q` + `scripts/eval_rules.py`（确认 `events` 与门禁未被影响）。
- 真机：用 `evaluation/scenarios/` 下的两份真实日志核对偏离清单是否符合直觉。
